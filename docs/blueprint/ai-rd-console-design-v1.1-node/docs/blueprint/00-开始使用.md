# AI 研发控制台：设计文档包

版本：v1.1（Node/TypeScript 架构重构稿）  
日期：2026-09-18  
状态：仅完成方案设计；平台代码、MCP 服务、测试与验收均未执行。  
工作名称：AI 研发控制台（暂定产品名 ForgeFlow）；示例项目代号 `RDC`，MCP 服务名 `rd-console`。名称不影响协议，可在开工前调整。

## 1. 这次确定的系统边界

本项目是“外部 AI 可读写的研发项目系统”，不是内置聊天机器人、远程 IDE 或自主多 Agent 开发平台。

- 人在网页里看项目、评审差异、批准任务、验收成果。
- 本地 Codex / Claude Code 通过 MCP 读取和维护项目资料。
- AI 使用自己已有的本地文件/终端能力，在业务项目仓库编写代码、运行测试。
- 平台接收版本、进度、问题、Diff、测试报告和验收证据，不默认启动 AI、不代管模型订阅、不远程运行任意命令。
- 同一套系统管理 Web 后台、工具软件、Godot 游戏等项目；具体设计章节和验证方式由轻量项目模板决定。

**平台数据库保存项目规格和流程事实；Git 保存代码、契约、迁移及导出的批准快照。导出文件不是第二套可双向编辑的状态库。**

## 3. 第一次怎样使用

1. 把文档包放到控制台项目仓库的 `docs/blueprint/`，保留相对文件名。
2. 把 `04` 中的“平台开发启动提示词”交给 Codex / Claude Code。
3. 第一轮只执行 S0 的设计核对和阶段拆分；不自动创建整套业务代码。
4. 人确认 S0 后，批准 S1 当前任务。S1 必须尽早打通真实 MCP 读写，而不是先做完漂亮界面。
5. S3 完成后，才能用平台正式授权外部 AI 编码并提交执行记录。S4 补齐严格技术验证、业务验收和交付。

平台尚未可用期间，使用本包的阶段清单记录启动工作；不要伪造“已通过平台批准”。平台闭环可用后，再一次性导入自己的项目资料，注明哪些批准是人工导入的历史事实。

## 4. 必须保持的十个不变量

| 编号 | 不变量 |
|---|---|
| I-01 | 没有有效执行授权，不允许把草稿规划理解为代码实施授权。 |
| I-02 | AI 身份不能批准设计、授予执行权限、确认人工验收或批准交付。 |
| I-03 | 已批准规格的内容不可覆盖；修改生成新版本。 |
| I-04 | Task 提交、Task 确认、Feature 验收、Release 交付分别记录。 |
| I-05 | 一个 Task 同时最多一个有效 Run；提交必须幂等。 |
| I-06 | 测试结果绑定实际代码/构建、用例版本和环境；未执行不等于通过。 |
| I-07 | AI 上报、采集器记录、独立 CI 验证和人工确认的证据来源不得混淆。 |
| I-08 | 页面进度来自结构化事实；未知状态不能自动换成 0% 或 100%。 |
| I-09 | Markdown/Git 导出只读；修改导出文件不会悄悄覆盖平台批准版本。 |
| I-10 | MCP 和规则文件不等于本地操作系统沙箱；平台不能保证控制有完整本地权限的外部 CLI。 |

## 5. 方案中的“已经核实”与“尚未执行”

已核实：官方文档支持 Codex / Claude Code 连接 MCP；MCP 官方 TypeScript SDK v2 已提供 Node.js、Streamable HTTP 与 Fastify 中间件；Node.js 24 当前为 LTS。数据库首版建议使用 SQLite + better-sqlite3/Drizzle，避免为了个人/少量并发场景额外维护 MySQL 服务。官方依据见 `03` 文末。

尚未执行：本项目 MCP 联调、Node 依赖构建、SQLite 迁移、界面实现、CLI 真实写回、性能和安全测试。因此所有端点、工具名、数据表和运行示例都是本项目的拟定契约，不是已部署能力。

你此前提供的菜单管理正文可作为导入测试材料；其关联文档和仓库没有在本轮实际读取，不能据此宣布代码已完成或任何验收通过。

## 6. 阅读负担控制

这套文档是控制台的开发蓝图，不是以后每次 AI 都要全量加载的上下文。日常执行只读：项目概要、当前任务、被引用的批准设计段落、必要代码入口和对应验证要求。

功能详情页默认显示摘要、当前任务、待你决策、设计差异与最新证据。全文和历史材料按需展开。
